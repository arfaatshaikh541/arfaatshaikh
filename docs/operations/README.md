# Executive Reporting & Operations

## Reporting cadences

All four reports below are generated by querying the World Model / audit log / Decision
Memory — **never freshly narrated from an open-ended model impression of "how things
went."** Every accomplishment claim links to its evidence (a completed workflow record,
a merged PR, a sent-and-confirmed communication, a reconciled transaction).

### Morning Brief

- Overnight events (Episodic Memory since last brief)
- Today's priorities (Goal Engine's active queue, ranked)
- Risks requiring attention (open Risk records above threshold)
- Meetings scheduled today, with prep status
- Decisions expected to be needed today (Approval Engine queue + Commitment Memory
  deadlines)

### Live Status

- Active goals and their current progress
- Active agents/workflows in flight (from the orchestrator, not self-report)
- Tasks currently queued/blocked/dead-lettered
- Spending so far this period vs. budget envelopes
- Recent communications sent
- Open incidents

### Evening Report

- Work completed (linked evidence)
- Business results: revenue, pipeline movement, customer activity
- Marketing activity and results
- Engineering activity (PRs, deploys, incidents)
- Operations activity
- Spending vs. budget
- Experiments run and their results
- Failures and what was learned (Failure Memory entries created today)
- Opportunities discovered
- Owner decisions still pending

### Weekly Board Report

- Strategy summary and progress against major goals
- KPIs (defined per business, sourced from Business Memory + Reconciliation Assistant)
- Financial performance (reconciled, not raw agent-reported)
- Growth metrics
- Product changes shipped
- Customer health (support volume, satisfaction signals, churn indicators)
- Operational health (incident count/severity, SLA adherence)
- Major risks
- Opportunities under consideration
- Next week's plan

## "What happened while I was away?"

A special-cased query spanning Episodic + Decision + Commitment memory from the owner's
last active session to now, rendered in the Evening Report format regardless of the
elapsed period's actual length (an hour or a month) — same structure, different time
window, so the owner always gets a consistent, navigable answer.

## Operational runbook essentials

- **On-call posture**: for a single-owner system, "on-call" means the owner is the
  ultimate escalation point for anything the Security Guardian freezes or the Approval
  Engine can't resolve; a hired ops contractor may hold a narrower operational on-call
  role for infra-level incidents (service down, not policy decisions) under their own
  scoped, audited access.
- **Incident handling**: any Security Guardian freeze or production incident creates an
  Incident record (World Model entity) with timeline, root cause (once known), and
  remediation — feeding both the Evening Report and Failure Memory.
- **Change management**: infrastructure and policy changes go through the same
  reviewed, versioned path as code (`docs/architecture/12-data-and-api.md#repository-
  architecture`); there is no separate "just SSH in and fix it" path for production, by
  design — that would itself be an unaudited privilege escalation surface.
